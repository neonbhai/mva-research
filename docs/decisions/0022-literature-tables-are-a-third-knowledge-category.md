# ADR 0022 — Literature-derived knowledge tables are a third category

**Status:** accepted · **Date:** 2026-08-28 · **Extends:** ADR 0012

## Context

Track 2 needs a mechanism chain and a drug catalogue for **BUB1B**, curated from the
published literature with a real citation behind every row. The repository already
holds two kinds of knowledge, and neither fits:

1. **Synthetic demo tables** (`knowledge/public/*.tsv`). Fabricated genes, invented
   numbers, shipped so the machinery can be exercised without a real case. Graded
   `synthetic-substitute` (GP-20).
2. **Acquired public reference data** (`knowledge/real/`, `tools/acquire/`). Real
   releases of gnomAD, ClinVar, HPO, MANE, pulled by an offline acquisition step and
   pinned by release version.

Literature curation is a third thing: it is real biology, it is not machine-acquired
from a versioned release, and its provenance is a **reading of specific papers by a
specific author on a specific date**. Its integrity claim is "this row is what
PMID 20516114 (Suijkerbuijk et al., *Cancer Res* 2010;70:4891-900) says", not "these
bytes match release v4.1".

The forcing constraint is mechanical. `mva.annotation.local_tables.compute_manifest`
globs `public/*.tsv` and stamps **`synthetic: true` unconditionally**, with no
per-table override. Dropping the BUB1B tables into `knowledge/public/` therefore
offers exactly two outcomes, and both are bad:

- regenerate the manifest and let it assert `synthetic: true` about literature
  curation — a false provenance claim in the one file whose job is provenance; or
- change `compute_manifest` so `synthetic` becomes a per-table flag — which puts a
  hand-set boolean between a reader and the question "is this real?", in the exact
  place where GP-20 says the answer must be unmissable.

## Decision

Literature-derived tables live in **`knowledge/literature/<gene>/`**, outside the
manifest's glob, and carry their own provenance in a sibling `SOURCES.md` that maps
every row to a citation with a PMID.

For BUB1B that is:

```
knowledge/literature/bub1b/
  mechanisms.tsv        # 12 nodes, 13 links, each individually graded
  mechanism_meta.tsv    # therapeutic target and required correction
  drug_catalog.tsv      # 13 agents, generated by tools/build_knowledge/bub1b_catalog.py
  SOURCES.md            # 55 references; every link_id and drug_id maps to one
```

The integrity check that suits this category is not a hash: it is that **every row
resolves to a citation, and every citation is used**. That is enforced as a test
(`tests/unit/test_track2_bub1b.py::test_every_curated_row_is_cited_in_sources` and
`::test_every_reference_id_used_is_defined`), in the same style as the `GP-nn` and
`ADR nnnn` link checks in `tests/unit/test_docs_integrity.py`. A dangling reference
ID fails the build in both directions: cited-but-undefined, and defined-but-unused.

The library version string is `bub1b-literature-v1`, deliberately unlike
`synthetic-v0.0`, because that string is stamped onto every downstream
`EvidenceItem` and is what tells a report reader which kind of table produced a
claim.

## Consequences

- The synthetic demo path is untouched. `knowledge/manifests/knowledge.yaml` does
  not change, `just demo` behaves identically, and no golden expectation moves.
- The BUB1B tables are **not** wired into `mva.pipeline`. They are loaded by the
  Track 2 test module through the ordinary public API (`MechanismLibrary.from_tsv`,
  `DrugCatalog.from_tsv`) — the same loaders the pipeline uses, with no parallel
  machinery. Wiring a gene-specific literature table into the composition root would
  make the pipeline's behaviour depend on which gene it happened to be looking at.
- The drug catalogue is **generated** from `tools/build_knowledge/bub1b_catalog.py`
  rather than hand-tabbed. The first hand-written version silently mis-aligned nine
  of thirteen rows by one tab, which shifted the `worsens_cin` column into the
  validation-experiment text. It failed loudly at parse time, but a column shift that
  happened to land on a parseable value would not have.
- **Known gap.** `mva.privacy.classify.classify_path` has no `knowledge/literature`
  entry in `_PUBLIC_PREFIXES`, so these files classify as `SENSITIVE` by the
  default-deny rule. Nothing currently exports them, so the effect is nil, and
  default-deny erring toward caution is the rule working as designed. Adding the
  prefix is deferred rather than done because `src/mva/privacy/` is owned by a
  concurrent workstream; recorded in `docs/tech-debt.md`.

## Alternatives rejected

**Put them in `knowledge/public/` and regenerate the manifest.** Rejected: it writes
`synthetic: true` about literature curation. The one documentation error GP-20 exists
to prevent is a synthetic substitute described as real; the mirror error — real
curation labelled synthetic — corrodes the same signal, because a reader who finds
one wrong `synthetic` flag stops believing any of them.

**Make `synthetic` a per-table override in `compute_manifest`.** Rejected here on
scope: it edits `src/mva/annotation/`, which is owned by another workstream, and it
turns an invariant ("everything in this manifest is fabricated") into a per-row claim
a curator can get wrong. If the repository later acquires many literature tables,
this becomes the right change, and this ADR is the record of why it was not made now.

**Inline the chain as Python constants.** Rejected: it makes curated scientific
content a code change, hides it from the TSV loaders' validation (referential
integrity, the direction triple, the two-record-type row check), and puts biology
behind a diff that reads as engineering.
